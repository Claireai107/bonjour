# 답변 방식 선택 화면 복구 (v1.5.0)

## 무슨 일이 있었나

앱을 다시 써보니 음성 모드로 들어갈 방법이 없었다.
처음에는 "선택 화면이 아예 없다"고 판단했는데, **틀렸다.**
`app/onboarding/page.tsx` ("어떻게 답하시겠어요?")는 그대로 있었다.

진짜 문제는 **그 화면을 아무도 거치지 않는다**는 것이었다.

```
app/home/page.tsx   [AI 뼈건강 분석 시작] → router.push("/survey")
```

홈에서 설문으로 직행하니 `/onboarding` 을 건너뛰고, `answerMode` 는
기본값 `"hand"` 그대로 설문에 들어갔다. `/onboarding` 으로 가는 링크는
`app/profile-add/page.tsx` (가족 프로필 추가) 한 군데뿐이었다.
즉 **가족 프로필을 새로 만들 때만** 답변 방식을 고를 수 있었다.

## 왜 이렇게 됐나

`docs/superpowers/plans/2026-07-13-navigation-report-flow.md` 의 목표에
이렇게 적혀 있다.

> route first-time users through **signup and home** before survey question 1

회원가입·홈을 설문 앞에 넣는 개편이었다. 그 과정에서 홈 → 설문 경로가
새로 생겼는데, 원래 그 자리에 있던 온보딩을 어디에 둘지는 계획서에 없다.
`app/onboarding/page.tsx` 는 "TabBar 를 추가한다" 항목으로만 등장한다.

그리고 이 동작이 **테스트로 못 박혀** 있었다.

```js
// tests/pageContracts.test.mjs (예전)
assert.match(home, /reset\(\);\s*router\.push\("\/survey"\)/);
```

화면은 멀쩡히 있고 테스트도 통과하니, 기능이 빠진 걸 알아채기 어려웠다.
세미1 발표 때는 이 개편 전이었거나 온보딩 화면을 직접 열어 보여줬을 것이다.

## 무엇을 바꿨나

**두 경로를 모두 둔다.**

1. **홈 → 답변 방식 선택 → 설문** (원래 설계)
   `router.push("/survey")` → `router.push("/onboarding")`.
   초기화(`reset()`)는 온보딩에서 방식을 고르는 시점에 하도록 옮겼다.
   홈에서 미리 지우면, 사용자가 뒤로 나갔을 때 답변이 이미 날아간다.

2. **설문 안에서 전환** (v1.4.1에서 추가, 유지)
   손 입력 화면의 [말로 답하기], 음성 화면 상단의 [손으로 답하기].
   온보딩 안내 문구가 원래 "설문 중에 언제든 바꿀 수 있어요"였는데,
   이제야 실제로 그렇게 된다. 문구도 "위쪽 버튼으로"라고 구체화했다.

**온보딩 화면에도 UT 개선을 반영했다.**

- 글자 크기 [가 가 가] 토글을 넣었다. 설문에 들어가기 전에 키울 수 있어야
  한다 (P4·P5가 글자 크기를 가장 불편한 점으로 꼽았다).
- 음성 인식을 지원하지 않는 브라우저에서는 [말로 답하기]를 흐리게 하고
  "크롬에서 열어주세요"로 안내한다. 골랐다가 막히는 것보다 낫다.
- "말로 답하기를 골라도 화면에서 손으로 고를 수 있어요" 안내를 넣었다.
  음성이 안 되면 갇힌다는 부담을 덜기 위해서다.

**테스트를 의도에 맞게 고쳐 썼다** (`tests/pageContracts.test.mjs`).

- 홈에서 `/onboarding` 으로 가는지, `/survey` 로 **직행하지 않는지**
- 온보딩이 손·음성 두 가지를 다 설정하고 초기화 후 설문으로 보내는지
- 설문 안에서도 `setAnswerMode` 를 양방향으로 부르는지

## 확인이 필요한 것

- **UT 태스크2(음성 입력)를 어떤 경로로 진행했는지.** 참가자들이 이 선택
  화면을 못 봤다면, 성공률 0%에 "음성 모드인 줄 모르고 손으로 답하려 했다"는
  원인이 섞여 있을 수 있다. 기획서에는 "자연어 표현 인식 실패"로만 적혀 있다.
- 화면이 하나 늘었다. 설문도 12문항으로 늘어난 참이라, 2차 UT에서 첫 진입
  소요시간(현재 평균 106.6초)이 어떻게 되는지 봐야 한다.

# 음성 모드 화면 정리 (v1.5.1)

## 무엇이 헷갈렸나

음성 모드 화면에 안내가 세 겹으로 있었다.

1. 연두색 박스 — "아래 버튼을 누르고 말씀해 주세요"
2. 실제 마이크 버튼 — "한 번 누르고 말하세요"
3. 그 아래 예시 문구 — "예) 안 해요, 하루, 사흘, 매일"

1번 박스가 버튼처럼 생겼는데 눌리지 않는다. 같은 말을 세 번 하면서
그중 하나만 진짜 버튼이니 헷갈릴 수밖에 없었다.

답을 확인하는 부분도 두 겹이었다. "인식된 답" 박스 + "이게 맞나요?" 문구가
따로 있는데, 아래 선택지에도 같은 값이 선택 표시로 나온다.

시작할 때 손/음성을 이미 골랐으니, 설문 화면에서 다시 설명할 필요도 없다.

## 무엇을 바꿨나

**대기 상태 안내 박스를 없앴다.** 안내는 마이크 버튼 하나가 맡는다.

| 상태 | 마이크 버튼 |
|---|---|
| 대기 | 여기를 누르고 말하세요 |
| 듣는 중 | 듣고 있어요… (박스 pulse) |
| 말한 뒤 | 다시 말하기 |

버튼에 초록 테두리(2.5px)를 둘러 눌리는 것임을 분명히 했다.

**결과 표시를 하나로 합쳤다.** 말한 뒤에만 나온다.

- 인식: `"하루" 로 듣고 1~2일 로 넣었어요` (연두)
- 실패: `"하루살이" 로 들었는데 잘 모르겠어요. 다시 말하거나 아래에서 골라 주세요.` (연빨강)

직접 골랐을 때는 아무것도 안 띄운다. 선택지에 이미 표시되기 때문이다.
"인식된 답" 박스와 "이게 맞나요?" 문구는 없앴다.

**하단 버튼 순서를 쓰는 순서대로 바꿨다.**
말하기(주 동작)가 위, [네, 맞아요]가 아래. 예전에는 반대였다.

**답 영역 라벨을 부담 없는 말로 바꿨다.**
"직접 고르기" → "아래에서 골라도 돼요" / "숫자를 직접 맞춰도 돼요".
음성을 고른 사람에게 "직접"은 실패했다는 뉘앙스로 읽힐 수 있다.

## 화면 구성 (정리 후)

```
[뒤로]  [진행바]  [손으로 답하기]

  본이 말풍선 — 질문 (누르면 다시 읽어줌)

  (말한 뒤에만) 인식 결과 또는 실패 안내

  아래에서 골라도 돼요
  [선택지 또는 숫자 입력]

─────────────────────────
  🎤 여기를 누르고 말하세요
     예) 안 해요, 하루, 사흘, 매일
  ✓ 네, 맞아요
```
