# 앱을 직접 써보고 잡은 문제 (v1.4.1)

UT와 별개로, 팀에서 앱을 다시 써보며 나온 네 가지.
두 개는 화면 문구 문제였고, 두 개는 기능이 실제로 잘못 동작하고 있었다.

## 1. 음성 모드로 들어갈 방법이 없었다 (가장 큼)

`setAnswerMode` 를 호출하는 화면이 **하나도 없었다.**
기본값이 `"hand"` 라서, 음성 모드 화면이 다 만들어져 있어도 아무도 볼 수 없었다.

```
lib/store.ts     answerMode: "hand"        ← 기본값
lib/store.ts     setAnswerMode: (m) => ... ← 정의만 있고 호출하는 곳 없음
```

UT에서 음성 태스크를 어떻게 진행했는지 확인이 필요하다.
진행자가 따로 열어줬거나, 배포본이 이 저장소와 다를 수 있다.

**고친 내용**

- 설문 화면(손 입력)에 **[말로 답하기]** 버튼 추가. 브라우저가 음성 인식을
  지원할 때만 보인다.
- 음성 모드 상단의 '음성 모드' 라벨을 **[손으로 답하기]** 버튼으로 바꿨다.
  들어갔다가 나올 길이 없으면 갇힌 느낌이 든다.

## 2. 또래 비교가 반대로 표시되고 있었다

점수 88점 · 등급 '좋음'인데 "상위 97%"로 적히고, 막대 표시는 '관리 필요'
쪽에 찍혔다.

원인은 `percentile` 의 뜻이었다. 이 값은 **"나보다 위험이 높은 또래의 비율"**
이라 클수록 건강하다. 그런데 화면은 '상위 몇 %'(작을수록 건강)로 쓰고 있었다.

| | 예전 | 지금 |
|---|---|---|
| 표기 | 상위 {percentile}% → 97% | 상위 {100−percentile}% → **3%** |
| 막대 위치 | 100 − percentile → 3% 지점 | percentile → **97% 지점** |
| 비교 문구 | percentile ≤ 50 이면 좋음 | percentile **≥** 50 이면 좋음 |

세 군데가 모두 같은 오해에서 나왔다. `lib/types.ts` 의 주석도
"상위 몇 % (낮을수록 건강)"이라고 잘못 적혀 있어서 함께 고쳤다.
회귀 테스트는 `tests/reportDisplay.test.mjs`.

**주의** — `percentile` 값 자체는 DA 쪽 `peer_percentile` 과 맞춰야 하므로
계산은 건드리지 않았다. 화면 표시만 바꿨다.

## 3. 시뮬레이터 '여기' 표시가 안 보였다

글자가 색 그라데이션 위에 그대로 얹혀 있어 묻혔고, 값이 양 끝으로 가면
화면 밖으로 잘렸다.

- 흰 배경 + 초록 테두리 칩으로 띄워 배경과 분리
- 위치를 6~94% 로 묶어 잘리지 않게
- 막대 위에 현재 값 점(16px)을 따로 찍어 어디인지 한 번 더 표시

## 4. "돌려서 고르기"가 무슨 말인지 모르겠다

회원가입 생년월일의 휠 피커를 여는 문구였다. 무슨 동작인지 안 드러난다.

- 버튼 문구: **"숫자 입력이 어려우세요?"** → 열면 **"숫자로 입력할래요"**
- 펼치면 안내 한 줄: "아래 숫자를 손가락으로 위아래로 밀어서 맞춰 주세요"
- `<details>` 를 걷어내고 일반 버튼 + 조건부 렌더링으로 바꿨다
  (`<details>` 삼각형 표시가 시니어에게 익숙하지 않다)

## 확인이 필요한 것

- **UT의 음성 태스크(태스크2)를 어떤 경로로 진행했는지** — 진입 버튼이
  없었다면, 태스크2 성공률 0%가 표현 인식만의 문제가 아닐 수 있다.
- 또래 비교 표시가 반대였던 게 UT 참가자 반응에도 영향을 줬을 수 있다.
  P3가 "이 결과가 맞나?"라고 한 대목을 다시 볼 필요가 있다.
