# 음성 입력 개선 (v1.2.0)

1차 사용성 테스트(2026.08.07~09, 40~60대 여성 5명) 결과 반영.
설문 음성 입력 태스크가 성공률 0% · 평균 157.8초로 전 태스크 중 가장 나빴다.

## 무엇이 문제였나

참가자 발음 문제가 아니었다. 인식은 됐는데 그 말을 값으로 바꾸지 못했다.

| 참가자 | 말한 것 | 예전 동작 |
|---|---|---|
| P1 | "운동 0일", "안 해요" | 값 없음 |
| P2 | "하루" | 값 없음 |
| P3 | "5~7일" | 숫자만 뽑아 **57**로 읽음 |
| P4 | "한 번" | 값 없음 |
| P3 | (인식 실패 후) | **고를 버튼조차 없음** |
| P5 | "눌러서 말하기" | 켜졌는지 몰라 재확인 |

세 번째와 다섯 번째가 특히 컸다. 음성 모드 화면에는 [네, 맞아요]와
[눌러서 말하기]뿐이어서, 인식이 실패하면 답을 넣을 방법이 아예 없었다.

## 1. 자연어 표현 인식 사전 확장

`lib/speechNormalize.ts` 를 새로 만들고, 인식 결과를 값으로 쓰기 전에
반드시 이 파일을 거치게 했다.

- `parseCount()` — 일수·횟수 (0~10)
- `parseKoreanNumber()` — 나이·키·몸무게 (백단위까지)
- `parseRange()` — "5~7일" 같은 범위

처리 순서: 0을 뜻하는 말 → 매일 → 범위 → 아라비아 숫자 → 순우리말 날짜
→ 수사+단위 순으로 본다. "0일도 안 해요"처럼 숫자와 부정이 같이 나오면
부정이 이긴다.

받아들이는 표현:

| 값 | 표현 |
|---|---|
| 0 | 안 해요 / 안함 / 없어요 / 전혀 / 하나도 / 0일 / 0회 |
| 1 | 하루 / 한 번 / 1번 / 1회 / 일주일에 한 번 |
| 2~7 | 이틀·사흘·나흘·닷새·엿새·이레 / 두 번~일곱 번 / 숫자 |
| 7 | 매일 / 날마다 / 맨날 / 거의 매일 |

**고칠 때 주의** — 단위를 떼는 정규식이 "세 번"을 통째로 지우지 않도록
앞에 최소 한 글자는 남긴다(`stripUnit`). '세'와 '번'이 둘 다 단위 목록에
있어서 생겼던 문제다.

### 문항별 구간 매핑

"하루"는 1인데 선택지는 `1~2일`(value 1)이라 숫자만으로는 못 맞춘다.
그래서 `lib/survey.ts` 의 문항에 `numberToChoice` 를 달았다.

- 근력운동: `0 → 안 함`, `1~2 → 1~2일`, `3~4 → 3~4일`, `5+ → 5일 이상`
- 수면시간: `<5 → 5시간 미만`, `<7`, `<9`, `그 외 → 9시간 이상`

라벨로 안 잡히는 말은 `voiceAliases` 에 넣는다 (예: 국민학교 → 초등학교).

## 2. 선택 버튼 상시 노출

음성 모드 화면에 **직접 고르기 / 직접 입력하기** 영역을 항상 띄운다.
음성이 되든 안 되든 보인다. 인식에 실패하면 그 영역으로 자동 스크롤한다.

터치 모드에서 쓰던 `ChoiceInput` · `NumberStepper` 를 그대로 재사용했다.

## 3. 녹음 상태 3단계 표시

`idle → listening → recognized / failed`

- 대기: "아래 버튼을 누르고 말씀해 주세요"
- 듣는 중: "듣고 있어요…" (박스 pulse + 시작할 때 진동 30ms)
- 인식됨: "'하루'로 인식했어요"
- 실패: "'○○'로 들었는데 잘 모르겠어요. 다시 말하거나 아래에서 골라 주세요"

버튼 문구도 `눌러서 말하기` → **`한 번 누르고 말하세요`** 로 바꿨다.
누르고 있어야 하는 줄 알고 헤매는 경우가 있었다.

무응답이 8초 넘으면 스스로 끊는다 (`SILENCE_TIMEOUT_MS`).

## 4. 말할 예시 미리 안내

각 문항에 `voiceHint` 를 달아 마이크 버튼 아래에 띄운다.
예) 근력운동 문항 → "예) 안 해요, 하루, 사흘, 매일"

## 테스트

```bash
npm test    # tests/speechNormalize.test.mjs 포함
```

## 남은 것

- 인식 실패율을 실제로 재보려면 2차 UT가 필요하다. 목표는 성공률 60% 이상,
  평균 소요시간 90초 이하.
- P3가 말한 "임신 한 번"은 이 저장소의 설문 10문항에 임신 항목이 없다.
  배포본과 문항 구성이 다른지 확인이 필요하다.

# 나머지 UT 개선 (v1.3.0)

## 글자 크기 (H6 · P4·P5)

가장 먼저 확인한 건 `app/layout.tsx` 의 `maximumScale: 1` 이었다.
이게 걸려 있으면 **손가락으로 확대하는 것조차 막힌다.** 시니어가 화면을
키울 방법이 아예 없었다는 뜻이다. `maximumScale: 5` + `userScalable: true` 로 풀었다.

그다음 두 가지를 했다.

1. **작은 글씨 하한 상향** — 코드 곳곳에 10~15px 하드코딩이 섞여 있었다.
   `tailwind.config.ts` 주석은 "최소 16px, 이보다 작게 금지"인데 지켜지지
   않고 있었다. 10·12·13px → 15px, 14·15px → 16px 로 올렸다.

2. **사용자 조절 3단계** — 보통 100% / 크게 115% / 아주 크게 130%.
   `<html>` 의 `--ts` 변수 하나만 바꾸고, 화면의 글자 크기가 모두
   `text-[length:calc(Npx*var(--ts))]` 형태로 이 값을 함께 쓴다 (233곳).
   버튼·터치 영역 크기는 그대로라 레이아웃이 덜 흔들린다.
   고른 값은 localStorage 에 남고, 첫 그리기 전에 적용해 깜빡임을 막는다.

   - `lib/textScale.ts` — 상태·저장
   - `components/TextScaleToggle.tsx` — [가 가 가] 토글
   - 놓은 자리: 마이페이지, 리포트 상단 (글씨가 작다고 느끼는 그 화면)

**글자 크기를 새로 쓸 때** 는 `text-[16px]` 대신
`text-[length:calc(16px*var(--ts))]` 로 적어야 조절 기능이 함께 먹는다.

## 리포트 표현과 시각화 (H3 · P1)

P1이 '영향 중간', '긍정 요인'의 뜻을 물었고, "위협 주요 요인이 한눈에 들어오지
않는다"를 가장 불편한 점으로 꼽았다. 개선 요청에서 부정-0-긍정 막대형을
직접 제안했고 그대로 반영했다.

- `components/FactorBar.tsx` — 가운데 0 기준선, 왼쪽 빨강(점수를 낮춘 항목) /
  오른쪽 초록(올려준 항목). 막대 끝에 "점수를 ○점 낮췄어요"처럼 점수로 적는다.
- 위험 요인과 보호 요인을 **한 목록으로 합쳐** 영향 큰 순 상위 5개만 보여준다.
  예전엔 두 카드로 떨어져 있어 비교가 안 됐다.
- 카드 제목: "뼈 건강을 위협하는 주요 요인" → **"점수에 영향을 준 항목"**
- 그 아래 한 줄로 근거를 적는다 — "체중이 점수를 가장 많이 낮췄어요".
  P3가 "뭘 해도 100점? 당황스럽네" 하며 결과 자체를 의심했는데,
  점수만 있고 왜 그런지가 없어서 생긴 일이었다.

## 시뮬레이터 (H4 · P1·P4·P5 / H5 · P2)

성공률 40%. 3명이 슬라이더를 찾거나 움직이는 데 도움을 받아야 했다.

- **점수 숫자를 크게 띄운다** — 예전엔 게이지 마커만 조금 움직여서
  "이동해도 왜 변화가 없지?"(P1) 소리가 나왔다. 이제 값이 바뀌면
  숫자가 0.4초 동안 굴러가고(`lib/useCountUp.ts`), `+3점` 배지가 0.8초 뜬다.
- **손잡이 32px → 44px**, 좌우 화살표 아이콘, 진입 시 2회 흔들림
  (`.animate-slider-nudge`). 라벨 밑에 "직접 움직여서 바꿔보세요".
- **상한 안내** — "체중과 근력운동만으로는 최대 ○점까지 올릴 수 있어요".
  이미 좋은 상태면 "더 올릴 여지가 적어요"라고 말해준다. 아무리 움직여도
  안 바뀌는 게 정상인 경우를 오류로 오해하지 않도록.
- **코치마크 1회** (`components/CoachMark.tsx`) — 처음 들어올 때만.
- **결과를 하단 고정으로** — 골절 위험 결과가 스크롤 아래에 가려져
  슬라이더와 같이 못 본다는 지적(P2)이 있었다. 이제 슬라이더를 움직이는
  동안 결과가 계속 보인다.

## 권한 (H6 · P2·P4·P5)

첫 진입 성공률 40%의 최대 병목. 5명 중 **2명이 휴대폰을 바꿔서** 진행했다.

`components/PermissionPrimer.tsx` 를 만들었다.

- 브라우저 권한 창을 띄우기 전에 무엇에 쓰는지 먼저 설명한다.
- `navigator.permissions.query` 로 이미 차단된 상태면 창을 또 띄우지 않고
  **해제 방법**을 안내한다 (반복 팝업이 P4를 붙잡았던 부분).
- 허용하지 않아도 직접 입력·직접 선택으로 끝까지 갈 수 있다.

현재 설문(마이크)에 붙였다. 카메라·위치용 문구도 같은 파일에 있으니
검진표 화면과 우리동네 화면에 같은 방식으로 붙이면 된다.

## 생년월일·주소 (H6 · P4·P5)

- 생년월일: **숫자 직접 입력이 기본**, 휠은 "돌려서 고르기"로 접어뒀다.
  자릿수를 채우면 다음 칸으로 넘어가고, 범위를 벗어나면 조용히 맞춘다.
- 주소: "도로명·동번지·건물명 모두 찾을 수 있어요" + 예시 세 개.
  진행자가 구두로 안내해야 했던 내용을 화면에 적었다.

## 검진 용어 툴팁 (H2 · P1·P4)

`lib/termGlossary.ts` + `components/TermTip.tsx`.
항목 옆 (?)를 누르면 그 자리에서 한 줄 설명이 펼쳐진다.
새 화면으로 넘기지 않는 이유는 입력하던 값이 날아가기 때문이다.

문구는 20자 안팎·한글 풀네임 병기·진단 표현 금지로 썼다.
**최종 문구는 팀 내 임상 인력 검수가 필요하다.**

## 확인이 필요한 것

- 2차 UT 전까지는 효과를 숫자로 말할 수 없다.
- px 값은 접근성 기준(WCAG 2.1 AA)에 맞춘 것이라, 실제 기기에서
  130% 상태일 때 레이아웃이 깨지는 곳이 있는지 봐야 한다.
